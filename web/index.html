04 / UNDERSTAND

Built to be explained

A portfolio should make its decisions and limits easy to inspect.

Five-minute walkthrough

  1. Generate and review a baseline scenario draft.
  2. Export it as JSON with its review state.
  3. Run commerce regression in the test lab.
  4. Inspect individual results and download the report.
  5. Run diagnostic mode and review its evidence-based explanation.
  6. Try sign-in, cart and checkout in the demo store.

Honest by design

Scenario templates and failure triage work without AI and are labeled as baseline / rule-based. An optional gateway can generate AI drafts after configuration.

Browser automation is executed with Playwright from the command line and in CI. The test lab runs fixed API checks; it cannot execute arbitrary code.

Run history is in memory; drafts use browser storage. This localhost demo has no production identity system.

Quality evidence

Desktop and mobile Chromium checks, API contracts, negative scenarios, accessibility scans, HTML/JUnit reports and failure traces.

Inspect CI artifacts ↗

Architecture

Browser → Node HTTP API → baseline / AI adapter / demo commerce / fixed suite runner.

Dependencies are limited to development tooling. Tests isolate sessions and use integer currency values.

OBSERVE / REPRODUCE / REPORT

Bug report builder

From an observed issue to a reviewable, Jira-ready draft.

Local · no AI or Jira access needed

Describe what you observed. Add the details you know; unknowns stay marked for confirmation. Nothing here creates a Jira issue or determines a root cause.

What went wrong?

Assess impact with your team. Blocker: flow cannot continue; Critical: severe data/security/business impact; Major: important function broken; Minor: limited impact; Cosmetic: appearance. Priority is decided in triage.

Jira-ready report

Draft · not submitted

No AI calls, server uploads or browser storage of bug details. Copy text does not attach a screenshot. Do not include confidential data unless your company permits using it here.
