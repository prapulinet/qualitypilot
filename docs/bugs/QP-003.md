# QP-003 · Saved draft history overflowed on mobile

**Severity:** Medium — saved draft review was inaccessible in Linux mobile Chromium CI.

**Evidence:** Run `41189802695` passed native Node 22/24 checks and 27 browser cases, but the mobile history-reload case timed out on both attempts. The trace reported review/history panels intercepting the history button click. The failure screenshot showed the history button exceeding its card width.

**Cause:** Implicit grid tracks and a flex history row retained their automatic minimum content width. A nowrap draft description could force the row outside its card.

**Fix:** Constrain history grid tracks with `minmax(0, 1fr)` and allow both history buttons and description flex items to shrink with `min-width: 0`.

**Regression:** The existing review/persistence/export workflow now uses a long reference string and checks document and history-row widths after reload before clicking. It still uses a normal actionable click; no force click or timeout increase bypasses the layout failure.

Local verification after the fix: both targeted history checks passed, followed by all 28 browser checks passing. Remote verification requires publishing the fix and checking a new Linux CI run.
